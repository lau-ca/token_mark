# 普通用户 Key 消耗分析设计

## 目标

在 `/dashboard/models` 所在的数据看板中新增普通用户专属的「Key 消耗分析」页签，让用户在与「模型调用分析」一致的时间范围和视觉体系下，查看自己每个 API Key 的请求量、Token 用量和消费金额。

## 页面与权限

- 新增路由 `/dashboard/keys`，作为现有数据看板一级页签。
- 页签仅在角色为普通用户时显示；管理员和超级管理员保持现有页签不变。
- 普通用户直接访问该路由时正常展示；非普通用户直接访问时回到「模型调用分析」。
- 页面复用数据看板现有 Tabs、筛选器、统计卡片、图表容器、表格、Skeleton、空状态和错误状态，不引入新的视觉语言。

## 数据范围

- 默认时间范围、快捷时间范围、手动时间范围和时间粒度与「模型调用分析」完全一致。
- 单次查询继续遵循普通用户数据看板最多一个月的限制。
- 返回当前用户所有未删除 Key，包括所选范围内零消耗的 Key。
- 所选范围内存在消费但已删除的 Key 仍返回，名称显示为本地化的“已删除 Key（ID）”。
- 完整 Key 不会返回前端，只返回服务端生成的脱敏 Key。

## 后端接口

新增：

```text
GET /api/data/keys/self
```

查询参数：

- `start_timestamp`：开始时间 Unix 秒。
- `end_timestamp`：结束时间 Unix 秒。

响应行按 `token_id + created_at` 聚合：

- `token_id`
- `token_name`
- `masked_key`
- `token_status`
- `accessed_time`
- `created_at`
- `count`
- `token_used`
- `quota`
- `deleted`

模型层先按当前用户过滤 `quota_data`，再读取该用户自己的 Token 元数据并合并，避免跨用户泄漏。数据库查询使用 GORM，兼容 SQLite、MySQL 和 PostgreSQL。

## 前端展示

### 顶部统计

复用模型分析统计口径和样式：

- 请求数
- 消耗
- Token 数
- 平均 RPM
- 平均 TPM

### 图表

复用模型调用分析的分析方式：

- 趋势：展示消耗最高的 Key 在时间轴上的变化，其余 Key 合并为“其他”。
- 占比：展示各 Key 在所选范围内的消耗占比。
- 排行：支持按消耗、请求数和 Token 数理解主要 Key 使用情况。

图表使用 Key 名称作为主标签、脱敏 Key 作为辅助识别信息；同名 Key 通过脱敏 Key 和 ID 区分。

### Key 明细

表格覆盖所有 Key，默认按消耗降序，支持名称搜索和列排序。字段包括：

- Key 名称与脱敏 Key
- 状态
- 请求数
- Token 数
- 消耗
- 消耗占比
- 最后使用时间

零消耗、已禁用和已删除 Key 都有明确状态，不隐藏用户需要核账的数据。

## 错误与空状态

- 请求失败时在对应区域展示与现有数据看板一致的错误占位，不保留旧数据冒充新时间范围结果。
- 没有 Key 时展示创建 Key 的说明性空状态。
- 有 Key 但所选范围无消费时仍展示全部 Key，统计为零。

## 验证

- 模型测试覆盖用户隔离、零消耗 Key、已删除 Key、脱敏 Key、时间范围聚合。
- 控制器测试覆盖无效时间范围和超过一个月限制。
- 前端类型检查、lint 和生产构建通过。
- 仅更新 `148.113.178.75` 的 `new-api-master`，不操作 worker、CPA 或 Nginx；部署后验证容器健康和 `/api/status`。
